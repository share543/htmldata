# data.html — 單檔離線資料管理工具

一個**單一 HTML 檔、零安裝、零網路、跨平台**的資料管理工具。用瀏覽器直接開啟即可使用：建立欄位、輸入資料、自動存檔、匯入／匯出，並能把多位同事各自建好的檔案**合併統整**。

設計場景：**站所業務各自建檔 → 匯出 JSON → 總部用同一工具多檔批次合併 → 匯出 `report.html` 相容 CSV 做分析**。

> **線上開啟**：<https://share543.github.io/htmldata/data.html>　·　**GitHub 專案**：<https://github.com/share543/htmldata>

```
業務A ─┐
業務B ─┼─ 匯出 JSON ──►  總部 data.html（多檔合併 + 判重） ── 匯出 CSV ──►  crm/report.html（分析報表）
業務C ─┘
```

---

## 快速開始

1. 用瀏覽器（Chrome / Edge / Firefox / Safari）開啟 `data.html`。
2. 右上角「**我的名稱**」填入自己的名字（會自動標記為每筆資料的建立者）。
3. 按「**範本**」套用 `customer.xlsx` 的 25 欄結構（只建欄位、不含內容）。
4. 按「**＋ 新增紀錄**」開始輸入；資料會**自動存入本機瀏覽器**。
5. 完成後按「**匯出 ▾ → 匯出 JSON**」，把檔案交給總部。

> 檔名 `data.html` 可自由改名或複製到不同電腦／手機，行為完全相同。

## 介面說明

工具列（由左至右）：

- **＋ 新增紀錄** — 開啟表單輸入新資料。
- **搜尋全部欄位…** — 即時關鍵字搜尋（含建立者）。
- **刪除(N)** — 刪除已勾選的紀錄（N 為勾選數）。
- **建立者下拉** — 依 `_owner` 篩選。
- **⚙ 欄位管理** — 新增／編輯／排序／刪除欄位。
- **範本** — 套用 25 欄客戶範本（取代現有欄位定義）。
- **⇪ 匯入 ▾**
  - 合併 JSON（多檔批次）…
  - 匯入 JSON（覆蓋目前資料）…
  - 匯入 CSV（新增紀錄）…
- **⇩ 匯出 ▾**
  - 匯出 JSON（供合併／備份）
  - 匯出 CSV（Excel 相容）
  - 匯出 CSV（供 report.html）…
- **■ 存檔（含資料）** — 下載自帶資料的 HTML 副本。
- **清除記憶** — 清空本機瀏覽器記憶（不影響已下載的檔案）。
- **◐ 主題** / **列印**

## 內建範本（customer.xlsx 25 欄）

按「**範本**」即建立下列欄位（不含內容）：

| 欄位 | 型別 | 備註 |
|---|---|---|
| 序號 | 流水號 | 新增時自動遞增（1、2、3…），不可手動修改 |
| 客代 / 公司名稱 / 收件地址 / 聯絡窗口 / 聯絡電話 / 聯絡信箱 / 商品類別 | 文字 | |
| 統編 | 文字(可選可打) | 保留前導零（如 `00121198`） |
| 日均量體 | 文字 | 可含範圍／單位（如 `5~10件/天`） |
| 預估營收/月 | 數字 | |
| 開發者 / 收貨站所 | 文字(可選可打) | |
| 課別 | 下拉 | 中課／北一課／北二課／北三課／南一課／南二課 |
| 填單日期～導入 | 日期 | |
| 結案 | 多行文字 | 附 Excel 現有範例可點選 |
| 說明 | 多行文字 | 附 Excel 現有範例可點選 |
| 洽談內容 | 多行文字 | 格式 `3/13 說明`（與 report.html 時間線一致） |
| 類別 | 下拉 | 1P(SCM)／3P(MO+)／零擔 |
| 甲指成功轉甲配 | 下拉 | 是／否 |

> 統編與日均量體維持「文字」型別，避免前導零遺失與範圍文字（`5~10件/天`）無法輸入。

> 欄位的 **key** 就是匯出 CSV 的欄名。key 不可包含 `=`、`;`、`,`。修改既有欄位的 key 時，既有資料會自動搬移。

## 檔案格式

### 匯出／合併用 JSON

```json
{
  "meta": { "tool": "data.html", "ver": 1, "exportedAt": "2026-09-24 12:00", "sheet": "未命名資料表", "owner": "王小明" },
  "schema": [ { "key": "公司名稱", "label": "公司名稱", "type": "text", "options": [], "examples": [], "hint": "", "default": "", "required": false } ],
  "records": [
    { "_id": "idxxxxxxxx", "_owner": "王小明", "_createdAt": "2026-09-24 12:00", "_updatedAt": "2026-09-24 12:00", "公司名稱": "…" }
  ],
  "owner": "王小明"
}
```

系統欄位（`_` 開頭）由工具自動維護，**請勿手動修改**：

- `_id` — 紀錄識別碼，合併時判斷「同一筆」的依據。
- `_owner` — 建立者。
- `_createdAt` / `_updatedAt` — 建立／更新時間。

## 合併規則

匯入多檔 JSON 時：

**更新（同 `_id` 但內容不同）**

| 規則 | 行為 |
|---|---|
| 以匯入檔覆寫 | 用匯入檔內容蓋掉我方（總部常用：業務更新回傳） |
| 保留我方 | 忽略匯入變更 |
| 兩者並存 | 匯入檔視為新紀錄（重新配發 `_id`） |

**疑似重複（判重欄位值相同、但 `_id` 不同）**

| 規則 | 行為 |
|---|---|
| 併成一筆，保留較新內容與我方識別碼 | 依 `_updatedAt` 判斷誰較新 |
| 併成一筆，以匯入檔覆寫內容 | 保留我方 `_id`，內容用匯入檔 |
| 併成一筆，保留我方內容 | 略過匯入檔內容 |
| 保留兩筆（不併） | 匯入檔另存為新紀錄 |

> 判重欄位需**雙方皆非空且完全相等**才算疑似重複（避免空值誤判）。合併過程一律保留 `_id`／`_createdAt`。

合併對話框另外提供兩項提示與選項：

- **欄位結構差異提示**：匯入檔有、我方沒有的欄位會列出來。這些值仍會存進紀錄，但因我方沒有對應的欄位定義，畫面不會顯示、也不會出現在 `report.html` 匯出 —— 建議先用「⚙ 欄位管理」補上再合併。
- **合併後重新編號流水號**：各站所的序號都從 1 起算，合併後難免重複。勾選此項會把序號重編為 1…N，讓報表上的序號可直接當識別用。**預設不勾選**，以免改變各站所原本熟悉的編號。

## 匯出給 report.html

`crm/report.html` 只接受 `.xlsx` / `.csv`，並以**純逗號分欄**解析（不處理引號）。因此本工具在匯出時會自動**淨化**每欄內容：

- 逗號 `,` → 全形 `，`
- 雙引號 `"` → 全形 `”`
- 換行 → `；`（但「收貨站所」欄改用 `/`）
- 多餘空白壓縮、去除前後空白
- 日期欄自動輸出 `YYYY-MM-DD`

對應的固定欄位為 25 欄：`序號, 客代, 統編, 公司名稱, 收件地址, 聯絡窗口, 聯絡電話, 聯絡信箱, 開發者, 課別, 收貨站所, 日均量體, 預估營收/月, 商品類別, 填單日期, 初步接洽, 需求確認, 報價, 簽約, 導入, 結案, 說明, 洽談內容, 類別, 甲指成功轉甲配`。

總部合併完成後，用「匯出 ▾ → 匯出 CSV（供 report.html）」，選擇欄位對應後下載，直接拖進 `report.html` 即可分析。

## 常見問題

**Q：資料存在哪裡？會被上傳嗎？**
不會。全部只存在你這台電腦的瀏覽器 localStorage（網域為 `file://`），無任何網路傳輸。

**Q：換電腦 / 換瀏覽器資料還在嗎？**
不在。localStorage 綁定瀏覽器與裝置。要帶走請用「**存檔（含資料）**」下載 HTML 副本，或用「匯出 JSON」。

**Q：資料會不會不見？**
建議定期按「存檔（含資料）」或「匯出 JSON」備份。若瀏覽器資料被清除，副本仍可還原。

**Q：瀏覽器顯示 localStorage 已滿？**
資料量大時請改用「存檔（含資料）」保存副本。分塊儲存已盡量利用容量，但 localStorage 總量仍有限。

**Q：合併後出現重複客戶？**
在合併對話框勾選「判重欄位」（例如統編），並選「疑似重複」處理規則為「併成一筆」。

**Q：可以直接編輯 data.html 嗎？**
可以。它只是一份 HTML，CSS/JS 全部內嵌，易於客製。

## 開發（改動 `data.html` 時）

工具本體 `data.html` 是**零依賴單一檔案**，直接用瀏覽器開就能跑、也能直接編輯。
但改動後請跑回歸測試：

```sh
npm install   # 只有第一次需要（安裝 jsdom；node_modules/ 已列入 .gitignore）
npm test
```

測試以 Node + jsdom 載入 `data.html`，並用**真實 UI 流程**驅動（實際點選單、派送選檔事件、按下套用合併），共 70 餘項檢查，涵蓋儲存格式相容、合併規則與計數、`report.html` CSV 契約、含資料副本、分頁可及性與離開頁面前補寫等。

> 為什麼不是 headless Chromium：Termux 環境下 `chromium-browser` 會因 `libtermux-exec.so` 的 namespace 問題無法啟動。
>
> 為什麼 `.npmrc` 要設 `bin-links=false`：Android 共享儲存（`/storage/emulated/0`）的 FUSE 不支援 symlink，npm 建立 `node_modules/.bin` 時會 `EACCES`。測試不需要任何相依套件的 CLI。
